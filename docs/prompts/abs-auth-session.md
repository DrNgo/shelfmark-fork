Design and implement an `abs` auth source for the Shelfmark fork: existing Audiobookshelf users can log into Shelfmark with their ABS credentials. Use the full superpowers process (brainstorming → spec → plan → subagent-driven execution with reviews) — this is auth code and warrants it.

**Repos:** `~/projects/shelfmark-fork` (the feature; commits to `main`) and `~/projects/fleet-infra` (deployment; GitOps via Flux, push = deploy).

**Investigation already done (verified 2026-08-01, re-verify only if the code moved):**
- Shelfmark auth sources live in `shelfmark/core/auth_modes.py`: `AUTH_SOURCES = (builtin, oidc, proxy, cwa)`. The **`cwa` source is the direct precedent** — it validates against an external system and auto-provisions users on first login (see `tests/e2e/test_auth_endpoints.py::test_login_cwa_provisions_db_user`). Add `AUTH_SOURCE_ABS` and a branch in `determine_auth_mode` gated on the ABS connection being configured (mirror how `oidc` gates on `OIDC_DISCOVERY_URL` + `OIDC_CLIENT_ID`).
- `shelfmark/core/external_user_linking.py::upsert_external_user` is the shared provisioning engine (used by CWA sync and OIDC): identity matching, username-collision strategies, role sync, creation. Call it with `auth_source="abs"` and the ABS user id as subject.
- Credential check = ABS `POST /login` with username/password; returns the user record incl. `type` (root/admin/user/guest). The fork already has an ABS client (`shelfmark/audiobookshelf/client.py`) and a configured URL from the library-matching integration.
- Frontend touchpoints: `AdminAuthSource` union + `authSourceLabel` in `src/frontend/src/services/api.ts` / `useUserMutations.ts`, `UserAuthSourceBadge`, and the AUTH_METHOD select in the security settings.

**Design decisions to settle with me in brainstorming** (my leanings in parens): role mapping (everyone provisions as `user`; builtin admin stays the only admin), fallback (builtin admins can still log in when ABS is down, mirroring how `oidc` mode admits builtin users — see `is_user_active_for_auth_mode`), which ABS users qualify (exclude `guest`, respect active flag), and what happens to the existing builtin non-admin users.
